# Dr. Mani’s Dental Clinic SEO implementation

## Phase 0 audit

The existing project renders its homepage as static HTML through a Node build on Vercel. Browser JavaScript runs the scroll-scrub hero, FAQs, booking handoff and overlays. The live service buttons expanded content in place, the doctor and policy links used hash overlays, and the sitemap listed the homepage only. The homepage had a static canonical and no homepage-level noindex. Legal templates published browser-visible placeholders and lacked crawlable policy routes and route-level noindex. The live page had both six-specialist and seven-doctor claims and cited credentials that need confirmation. Both marquee rows already marked their cloned items aria-hidden.

The baseline HTML was 14,296,423 bytes before transfer compression. It carried inline images and the 150-frame hero pack, a blocking Google Fonts stylesheet with display swap, a branded loading layer and a video fallback set to preload automatically. The project was already serving complete homepage HTML. Moving the services, team, location and policies to static routes addressed the JavaScript-dependent navigation without an SSR framework.

Run `node build.js` to generate the deployable site and `node build.js --review` for draft articles and the page metadata inventory. The original homepage and fallback video source remain the build inputs. The JSON-LD blocks are rendered as literal HTML in every page. The 404 and interim policy pages carry noindex and are excluded from the sitemap.

The supplied homepage description was 162 characters. The implemented 157-character version removes “Call” and keeps the clinical offer and phone number. The existing hero eyebrow is the H1 slot. Its visible words now include “Dentist in Karaikudi” and the Tamil heading remains visible as an H2. The loading layer no longer delays the initial view. The original poster, 150 hero frames, scroll timing and fallback video bytes were retained. External images use descriptive, fingerprinted names and intrinsic dimensions. Below-fold images lazy-load. The original file formats remain in use for the initial release. Fonts keep the original family choices and display swap. The Tamil font request uses only glyphs present in the homepage. The hero reserves its existing cinematic layout before first paint and the high-priority poster precedes the lower-priority frame pack. The homepage map loads after opt-in. The location page also offers a link to load its map deliberately.

## Mobile baseline

[PageSpeed Insights baseline](https://pagespeed.web.dev/analysis/https-www-drmanisdentalkaraikudi-com/jo39yajbum?form_factor=mobile) reported Performance 32, SEO 100, LCP 53.1 seconds and CLS 0.71. The first deployed audit reported Performance 55 and SEO 92. It identified the hero card’s late layout switch and the nine “Learn more” labels. The follow-up fixes address both findings. The baseline contained no CrUX field data for INP. The lab sample is one run and may vary.

## Post-launch checklist

1. Verify the new and old domains as Search Console properties, preferably using DNS. Submit `https://www.drmanisdentalkaraikudi.com/sitemap.xml`. Inspect and request indexing for the homepage, service directory, key service pages and location page.
2. Add confirmed old paths to the redirect deployment. Verify the old hosts, TLS and exact 301 destinations. Submit Change of Address from the old property once redirects are working and keep redirects in place for at least one year.
3. Update the Google Business Profile website, relevant directory citations and links pointing to the old domain. Verify address, phone, hours, maps/review links and canonical host.
4. Run Google Rich Results Test and Schema Markup Validator on the homepage, a service, the founder and location routes. Add confirmed Business Profile URL, geo, map URL and service area details when available.
5. Inspect all sitemap URLs for HTTP 200 and test a missing route for HTTP 404. Check HTTP and HTTPS, www and apex redirect status and hops. Vercel controls HTTP-to-HTTPS at the edge. The application-level apex-to-www rule explicitly requests 301.
6. Compare mobile Lighthouse runs on the same settings and check Search Console Core Web Vitals when field data is available. Validate LCP, INP and CLS in addition to SEO and Performance scores. Confirm visual parity on mobile and desktop before any further video encoding or font changes.
7. Add measurement for call, WhatsApp, directions and submission only after resolving analytics and consent. No analytics or event reporting was added here.
